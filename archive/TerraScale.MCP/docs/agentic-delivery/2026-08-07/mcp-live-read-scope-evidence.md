# MCP live configured-project evidence tranche

Ownership claim: `TerraScale.MCP` only; `tests/TerraScale.MCP.Tests/LiveReadScopeE2ETests.cs`, `.forgejo/workflows/mcp-live-evidence.yml`, `README.md`, and this report. Base revision: `295f15e` on `develop`. No shared fixture, database, port, queue, or deployment was used locally. Forgejo workflow concurrency is fixed, but no supported fixture lease/acquire/verify/release system exists, and this work does not claim one.

The new discovery-time-gated E2E starts two real MCP stdio processes and invokes only `get_configured_project`. That MCP tool uses the public typed `Projects.GetAsync` GET. The success process uses the approved configured project; the other process uses the protected configured expected-403 project with the same least-privilege bearer credential. It validates the documented SafeProject projection and configured scope, then validates the reduced safe 403 envelope. It also checks MCP response/stdout/stderr for fixture credential, API address, and expected-403 project ID leakage. The configured project ID is deliberately present only in its documented safe projection. The tranche performs exactly two fixed GETs and no mutation.

The expected-403 check is not evidence that the configured expected-403 ID exists, is out of scope, or represents generic authorization behavior; those conclusions require independent external service evidence. The protected manual workflow fails without its required protected configuration, when the test skips, or when it fails. It has a credential-free `develop` ref/commit preflight, repeats the guard immediately before testing, and uses `git rev-parse HEAD` for the persisted commit. The `mcp-live-evidence` Forgejo environment must be branch-protected to `develop`; otherwise an arbitrary workflow ref could receive its step-local fixture secrets. The sole persisted artifact contains only commit, selector, result, and timestamp. No external lease is acquired, verified, released, or claimed; a concurrent fixture/control-plane change can cause a failed check and cannot be serialized by this workflow.

Fixture API values are scoped only to the one test step, never the job or artifact-upload step. Locked restore, Release build, and `VerifyLiveEvidenceTrx.cs --self-test` complete before secrets are injected. The helper uses secure BCL `XmlReader` settings (DTD prohibited, resolver disabled, bounded document), then namespace-aware BCL XML queries. It advances through the normal XML declaration before requiring canonical TRX `TestRun` root/namespace and the exact direct hierarchies `TestRun → Results → UnitTestResult` and `TestRun → ResultSummary → Counters`, rejecting any misplaced matching descendant. Self-test covers canonical pass plus malformed XML, multiple results, counter mismatch, foreign-namespaced required counter/result attributes, and same-namespace misplaced or nested result/counters. The live test is then invoked with `-c Release --no-build --no-restore`, its exact fully qualified method name, and a temporary TRX logger. Before writing an artifact, the helper requires exactly one intended `UnitTestResult` with unqualified `testName`/`outcome` attributes and `Passed` outcome, exactly one `Counters`, and exact total/executed/passed=1 with failed/error/timeout/aborted/inconclusive/notExecuted=0; every required counter must be an unqualified attribute. A skip or zero discovery cannot attest. The temporary TRX and test output are removed by the step trap. No checked-in Forgejo workflow established a supported `forgejo.ref` expression pattern, so this tranche intentionally does not invent one: the credential-free preflight and test-step shell guards verify `GITHUB_REF`, fetch `origin/develop`, require `git rev-parse HEAD` to equal that remote commit, and reject any mismatch before the test is invoked.

The `mcp-live-fixture` runner label and fixed Forgejo concurrency remain only an external operator-controlled exclusive-lane prerequisite. A dedicated non-overlapping fixture runner/environment must be evidenced externally; this workflow neither acquires nor proves a cross-host lock. Without that external evidence, a live result cannot be credited as release evidence. Concurrent fixture/control-plane activity can make the check fail.

This is live GET/scope-denial evidence only. Remaining unproven live routes are regions; databases; environments; usage; latency; workload/history; backup and restore-job inspection; pagination; resources; prompts; configuration failures; transport failures; cancellation/timeouts; and backup-plan admission. No MCP mutation, SDK change, raw SDK request, fake server, AppHost/DevHost, registry, release, or external service change is included.
